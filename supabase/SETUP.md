# ตั้งค่า Supabase สำหรับ FLOWLOCK

1. สร้างโปรเจกต์ Supabase แล้วเปิด SQL Editor
2. วางและรัน `supabase/setup.sql` (รันซ้ำได้เพื่ออัปเดต schema; สร้างระบบเพื่อน คำเชิญห้องเกม/เทรด ข้อเสนอเทรดส่วนตัวที่เปิดเผยเมื่อทั้งคู่ยืนยัน และ private bucket สำหรับรูปโปรไฟล์) โดยต้องรันกับโปรเจกต์เดียวกับ Project URL ใน `assets/js/supabase-config.js`
3. ใน Authentication settings ให้ปิดการยืนยันอีเมล (Confirm email) เนื่องจาก FLOWLOCK ใช้ชื่อผู้ใช้ ไม่ได้เก็บอีเมลสำหรับรับลิงก์ยืนยัน
4. คัดลอก Project URL และ anon/publishable key จากหน้า API settings ไปใส่ใน `assets/js/supabase-config.js`
   - ใช้ได้เฉพาะ anon/publishable key ในเว็บไซต์
   - ห้ามใส่ service_role/secret key ในไฟล์หน้าเว็บ
5. เผยแพร่เว็บผ่าน HTTPS แล้วสมัครสมาชิกใหม่หรือล็อกอินจากอุปกรณ์อื่นด้วยชื่อผู้ใช้และรหัสผ่านเดิม

ตรวจสอบใน SQL Editor ของโปรเจกต์เดียวกันได้ด้วย `select public.get_flowlock_user_count();` ฟังก์ชันค้นหาสมาชิกด้วย UID หรือชื่อผู้ใช้ และ RPC จัดการเพื่อนจะคืนเฉพาะข้อมูลที่จำเป็นต่อผู้ใช้ที่เข้าสู่ระบบ

บัญชีเดิมที่สมัครก่อนเชื่อม Supabase จะถูกเก็บอยู่เฉพาะในเบราว์เซอร์เดิม ให้ออกจากระบบแล้วล็อกอินอีกครั้งจากเครื่องเดิมเพื่อย้ายบัญชีขึ้นระบบกลาง หลังย้ายแล้วจึงใช้บัญชีจากเครื่องอื่นได้ บัญชีเดิมที่ไม่มีข้อมูลในเบราว์เซอร์ต้นทางต้องสมัครใหม่

รูปโปรไฟล์ถูกเก็บใน private bucket และแต่ละบัญชีเข้าถึงได้เฉพาะไฟล์ของตนเอง ส่วนคำขอเพื่อน รายชื่อเพื่อน ห้องเกม และห้องเทรดจะเก็บบน Supabase ข้อเสนอเทรดถูกเก็บแยกและอ่านผ่าน RPC ที่เปิดเผยข้อมูลของอีกฝ่ายเมื่อทั้งสองยืนยันแล้วเท่านั้น โดยรองรับเฉพาะลิงก์กระเป๋าเงิน, ไอดีสาธารณะ และโค้ดแลกรับที่ไม่ใช่ข้อมูลเข้าสู่ระบบ ห้ามส่งรหัสผ่าน, OTP หรือรหัสกู้คืน ห้องเกมที่เปิดปกติจอยได้ด้วยรหัส ส่วนห้องที่ส่งคำเชิญแล้วจะจำกัดเฉพาะผู้เข้าร่วม และผู้ได้รับเชิญสามารถเข้าร่วมหรือปฏิเสธคำเชิญได้ ห้องเกมปกติสามารถเติม AI ได้ โดยเครื่องของเจ้าของห้องจะประมวลผลตา AI ข้อความท้าทายแยกเก็บและเปิดให้อ่านเฉพาะผู้ชนะเมื่อเกมจบ ระบบจะตรวจข้อมูลใหม่เป็นระยะเพื่ออัปเดตคำเชิญและสถานะข้ามอุปกรณ์

ข้อมูลเพื่อนและห้องเดโมที่เคยเก็บใน `localStorage` จะไม่ถูกย้ายอัตโนมัติ ให้ส่งคำขอเพื่อนใหม่หลังอัปเดต schema

หากหน้าเทรดแจ้งว่าไม่พบ RPC หรือไม่พบตารางข้อเสนอ/ความพร้อม ให้รัน `supabase/migrations/20261125_trade_flow.sql` ใน SQL Editor ของโปรเจกต์ที่เว็บไซต์เชื่อมต่ออยู่ ไฟล์นี้ติดตั้งตารางและ RPC สำหรับเทรด พร้อมสั่ง reload schema cache หาก SQL แจ้งว่าไม่มี `flowlock_shared_rooms` หรือ `flowlock_profiles` ให้รัน `supabase/setup.sql` ทั้งไฟล์ก่อน จากนั้นตรวจว่าฟังก์ชันถูกติดตั้งด้วยคำสั่งนี้:

```sql
select pg_get_function_identity_arguments(p.oid)
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public'
  and p.proname = 'set_flowlock_trade_ready';
```

ผลลัพธ์ควรเป็น `room_id text, is_ready boolean` หากมีฟังก์ชันแล้วแต่ยังพบข้อความเดิม ให้สั่ง reload schema cache:

```sql
notify pgrst, 'reload schema';
```
